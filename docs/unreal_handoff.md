## Run

Start the Python service in one terminal:

```powershell
Set-Location D:\Life_v2
uv run xeno serve
```

In another terminal, launch the minimal mission:

```powershell
.\scripts\Run-XenoUnreal.ps1
```

This launches the compiled project in game mode, connects to the API, and runs an automated
transport demonstration. The 3D view contains a procedural rocky basin, ridgelines, outcrops,
a field station and a six-wheel rover. The compact HUD shows real mission budgets, samples
and paired control/treatment measurements. The rover interpolates between committed service
poses and visually follows the presentation terrain.

Camera controls: hold the right mouse button and drag to orbit, scroll to zoom, use A/D to
turn, and press R to reset. A closer framing can be launched with `-View Rover`; the default
is `-View Overview`. These are viewing controls and do not submit scientific actions.

To rebuild the editor module and regenerate the two scene assets:

```powershell
.\scripts\Build-XenoUnreal.ps1 -Target Editor
```

To build a Windows Development package and test its standalone executable:

```powershell
.\scripts\Build-XenoUnreal.ps1 -Target Package
.\scripts\Run-XenoUnreal.ps1 -Mode Packaged -Smoke
```

Remove `-Smoke` for the visible packaged window. Smoke mode runs with NullRHI and exits after
verification. The editor game-mode check is `Run-XenoUnreal.ps1 -Smoke`. Scripts discover the
engine through the Epic Launcher manifest; `-EngineRoot` or `XENO_ENGINE_ROOT` overrides it.
They use the existing service on loopback port 8766 and do not stop other applications.

## Runtime boundary

`UXenoSimulationBridge` is C++, using the runtime HTTP and WebSockets modules. No Python
interpreter, admin credential or private checkpoint is present in the gameplay client.
The only Unreal Python script creates assets in the editor during setup.

The trusted launcher creates an episode using the local admin credential, then writes only
its scoped investigator credential to `runs/unreal-*/session.private.json`. The child receives
the **path** through `XENO_SESSION_FILE`; credentials are not placed in command-line arguments,
assets, configuration or log messages. Keep these session files private. Local filesystem
isolation from the same OS account remains outside the current security claim.

The bridge verifies model and observation schema versions, submits actions with UUIDs and
revisions, deduplicates stream events, and requests resynchronization on sequence gaps.
It stops on transport failure without issuing a new sample action after a timeout.
Automatic reconnect and user-facing retry controls remain future improvements.

The visible demo intentionally reports an inconclusive scientific outcome and score 0.5.
It validates transport and inventory behavior. The existing headless investigation policies
remain separate from this transport demonstration.

5. Submit an evidence-linked inconclusive conclusion.
6. Require revision 6, all seven stream events, and an unchanged result on duplicate collection.
7. The trusted launcher checks one lab action, exactly one collection volume and a total

Each run stores `runtime-check.json`, `unreal.log`, a private scoped session and, for smoke
runs, `evaluation.private.json`. Rendered successful runs also request `preview.png`.
The local packaged archive is `runs/unreal-package/Windows/`; it is not published.

## Scope

World metres convert to Unreal centimetres and then use an explicitly labelled 100x artistic
magnification. Terrain relief, sky, fog, rocks, rover geometry and lights are presentation
assets; they do not calibrate a planetary environment or alter the chemistry. Rendering does
not own scientific time. The point-rover model has no terrain collision constraints; camera
observations as scientific instruments, manual rover driving and data field overlays remain
future work.

The runtime source is separated into `XenoEnvironment` (terrain and dressing), `XenoRover`
(vehicle geometry and pose interpolation), `XenoMissionMode` (orchestration/camera), `XenoHUD`
(public observations), and `XenoSimulationBridge` (authenticated protocol). Materials are
generated by the editor-only setup script and are explicitly included in cooking.

For an editor-only normal-buffer diagnostic, use
`Run-XenoUnreal.ps1 -Mode EditorGame -RenderPass WorldNormal`. Normal runs use `-RenderPass Lit`.
The procedural mesh implementation is pinned to the checked engine version; the module's
upstream API is marked experimental.

and [build, cook, stage and package](https://dev.epicgames.com/documentation/en-us/unreal-engine/packaging-your-project).
